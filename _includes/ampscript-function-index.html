{% comment %} Renders the searchable / filterable / sortable AMPscript function catalog table. Shares its shape and `.cat-*` styling (in _sass/_function-index.scss) with handlebars-helper-index.html so the two catalogs stay visually and behaviourally aligned instead of drifting apart. Usage: {% include ampscript-function-index.html entries=site.data.ampscript_functions empty="No functions catalogued yet." %} Parameters: entries (array) - a site.data.* list of function rows (may be empty/nil). empty (string) - sentence shown when there are no entries. mcn_only (bool) - keep only rows available on Marketing Cloud Next (non-empty `mcn`). Default: show everything. show_mcn (bool) - add the "API version" column and its sort mode. show_handlebars (bool) - add the "Handlebars" column (equivalent helper + the MCN caveat from `mcnNotes`). show_mapping (bool) - add the "Handlebars mapping" filter without the column (show_handlebars implies this too). show_ssjs (bool) - add the "SSJS" column (equivalent Platform function, linking out to ssjs.guide). show_ssjs_mapping (bool) - add the "SSJS mapping" filter without the column (show_ssjs implies this too). A column requested only through its *_mapping filter is still emitted, hidden by default, and revealed by JS while that filter narrows the list — so the equivalents you filter by are visible. Row fields come from scripts/generate-ampscript-function-index.mjs: name, slug, category, syntax, returnType, verified, url, differsFromDocs, deprecated, mcn, handlebarsEquivalent, mcnNotes, ssjsEquivalents (list of {name, url}), description, guideUrl A row is only linked when `verified` is true — an unverified row is catalogued, not proven, and must never link to a page that does not exist. Verification always happens on Engagement, so the link target stays under /engagement/ even when the table is rendered in the Next section. `description` MUST be escaped.
