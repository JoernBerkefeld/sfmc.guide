## Parameters

| Name | Type | Required | Description |
|---|---|---|---|
| `stringToConvert` | string \| number \| date | Yes | The value to hash |
| `charSet` | string | No | Name of the character encoding applied before hashing; defaults to UTF-8. Next accepted `UTF-16`; `ASCII` and unknown names are rejected at save |

## Example

```ampscript
%%=SHA512("abc")=%%
```

Renders a 128-character digest beginning `ddaf35a193617aba`.

## Return value

**`string`** — 128 lowercase hexadecimal characters with no separators.

There is no error token to test for: every accepted call returns a digest.

## Behaviour

**The digest is standard SHA-512.** `SHA512("abc")` gives the well-known digest beginning `ddaf35a193617aba`, and `Length(SHA512("Hash probe 2026"))` gives `128`.

**The empty string is hashed.** `SHA512("")` gives the digest of zero bytes, beginning `cf83e1357eefb8bd`.

**UTF-8 bytes are hashed by default.** `SHA512("Grusß €ä")` gives a digest beginning `cf46d118822edbf2`.

**`UTF-16` changes the digest.** `SHA512("Grusß €ä", "UTF-16")` gives a digest beginning `133c85ecdfdec3f5`.

**`ASCII` and unknown names are refused at save.** An email containing `SHA512("Grusß €ä", "ASCII")` or `SHA512("Hash probe 2026", "banana")` cannot be saved: the content API answers HTTP 400 with "The AMPscript syntax isn't valid".

**Wrong argument counts are refused at save.** `SHA512()` and a call with three arguments are rejected the same way.
