## Parameters

| Name | Type | Required | Description |
|---|---|---|---|
| `stringToConvert` | string \| number \| date | Yes | The value to hash |
| `charSet` | string | No | Name of the character encoding applied before hashing; defaults to UTF-8. Next accepted `UTF-16`; `ASCII` and unknown names are rejected at save |

## Example

```ampscript
%%=SHA256("Hash example 2026")=%%
```

Renders `e532741701758f26f517edcfb7632749359a72fb0246cd1244e7a0f5251fbfcd`.

## Return value

**`string`** — 64 lowercase hexadecimal characters with no separators.

There is no error token to test for: every accepted call returns a digest.

## Behaviour

**The digest is standard SHA-256.** `SHA256("abc")` gives `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`, and `Length(SHA256("Hash probe 2026"))` gives `64`.

**The empty string is hashed.** `SHA256("")` gives `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`, the digest of zero bytes.

**UTF-8 bytes are hashed by default.** `SHA256("Grusß €ä")` gives `eae41ff0f6fc4b2347b9a39213e5149c2730b90296234396f0ae8b961732bfec`.

**`UTF-16` changes the digest.** `SHA256("Grusß €ä", "UTF-16")` gives `d30fcad4e2f349d1f3a341afbd5ef5dd9770eb2cd30607a775edf252807535e6`, and `SHA256("Hash probe 2026", "UTF-16")` gives `b30cb452193f7d2228a7a89cc5f8f3831fabb63df4e933b1dd985470cf161c89`.

**`ASCII` and unknown names are refused at save.** An email containing `SHA256("Grusß €ä", "ASCII")` or `SHA256("Hash probe 2026", "banana")` cannot be saved: the content API answers HTTP 400 with "The AMPscript syntax isn't valid".

**Wrong argument counts are refused at save.** `SHA256()` and a call with three arguments are rejected the same way.
